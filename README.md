# Video-Grabing

一个跨平台的**视频 + 音乐**采集器：粘贴链接或 App 分享文案就能解析并下载，
支持 **B站 / 抖音 / 小红书 / 芒果TV / 腾讯视频 / 优酷 / 爱奇艺** 七个视频平台，
以及 **网易云音乐 / QQ音乐 / 酷狗音乐 / 酷我音乐** 四个音乐平台。

还能把各音乐平台下载到的**加密专属格式**（.ncm / .qmc / .mflac / .kgm / .kwm …）解密成通用音频，
并按你选的格式输出。

- **十一个平台**，粘贴链接即可自动识别；音乐可选音质与格式
- 在 B 站上做到了 **十条互相独立的抓取通道**，可自选清晰度、可勾选分 P 批量下载
- **独立桌面窗口**：内置 WebView2 渲染；**任何情况下都不会弹出浏览器**
- **本地文件转换**：解密平台加密格式 → 转成 mp3 / flac / m4a / wav / ogg / opus
- **多线程断点续传下载**；没有 ffmpeg 也能合并 DASH 音视频，HLS 分片也能拼成文件
- 后端 **纯 Python 标准库**，零第三方依赖，`python start.py` 即可运行
- 前端原生 HTML / CSS / ES Module，没有构建步骤
- 带 **.exe 安装程序**、**一键自动更新**（下载完自动装好并重启）与 **自检修复**（比对仓库基线哈希，坏了自动重下）
- **删除任何文件之前都会列出具体清单**，你确认了才动手
- 安装时永远装进自己的 `VGPlatform` 子目录，不会和你的文件混在一起
- 适配 Windows 缩放比例（Per-Monitor V2 DPI），高分屏不发虚

### 抖音

  得到的一整段分享文案（会自动从中提取短链）。
- **能拿到什么**：**无水印的成品直链**（H.264 / H.265 单文件已含音轨，不需要合并），
  可选 2160P / 1440P / 1080P / 720P / 576P / 540P，按传入的清晰度要求挑档。
  元数据包含标题、时长、发布时间、作者（含粉丝数）和封面。
- **实测**：`douyin.com/video/7577614489533680959` → 4K HEVC 单文件 377.7 MB 完整下载成功。
- **限制**：douyinvod 的 CDN 强制校验抖音 Referer（程序已经按平台带对了）；
  私密作品、已删除作品取不到，会如实报错。

### 小红书

- **支持的输入**：`xhslink.com` 短链、`www.xiaohongshu.com/explore/{id}`。
- **能拿到什么**：视频笔记的成品 mp4（含音轨），以及标题、时长、发布时间、作者、
  点赞 / 收藏 / 评论 / 分享数。
- **实测**：`xiaohongshu.com/explore/69d241ab000000002301fc7d` → 720×1280 / 14.9 MB，
  另有 2 条备用 CDN。
- **限制**：**只支持视频笔记**，图文笔记会把元数据正常给你、但在取流时明确说明"这是图文笔记"。
  国内站无 `xsec_token` 时只回登录壳，程序会自动兜底走国际版 RedNote 的移动页；
  仅国内可见的笔记因此取不到（报错里会写清楚）。

### 芒果TV

- **支持的输入**：`www.mgtv.com/b/{合集号}/{视频号}.html`。
- **能拿到什么**：元数据 + **完整的分集列表**（一集不漏，带真实剧集标题和时长），
  播放地址是 720P / 576P / 480P 三档 **HLS**。
- **实测**：明星大侦探第四季 → 25 个分集、31 个分片拼成 46.1 MB；
  夏日少年派、大侦探11季 同样跑通。
- **关于 HLS**：这是全项目唯一只下发 HLS 的平台。程序内置了纯标准库的
  m3u8 分片下载器（并发拉取 + 按序拼接），输出 **MPEG-TS**。
  VLC / PotPlayer / mpv 都能直接播；**装了 ffmpeg 会自动转封装成 MP4**。
  如果播放列表带 `#EXT-X-KEY`（AES-128 加密），会明确报错而不是产出坏文件。
- **限制**：1080P 需要会员（接口标记 `vip=1`，界面会把它列成"虚报档位"）；
  播放地址带时效。部分地区/版权内容会返回 `not available in this country/region`，如实报错。

### 腾讯视频

- **支持的输入**：`v.qq.com/x/cover/{cid}/{vid}.html`、`v.qq.com/x/page/{vid}.html`；
  给合集地址（`/x/cover/{cid}.html`）会自动取第一集。
- **能拿到什么**：带 `vkey` 的 **MP4 直链**（附 3 条备用 CDN）、封面、简介、正片列表。
  多集内容用 `page` 参数切集。
- **实测**：现在就出发S4（会员剧集）→ 自动从默认 480P 升到 **720P**；
  纯 UGC 视频 → 完整 720P / 58.5 MB。
- **限制**：会员内容只下发约 **180 秒试看**（接口 `preview=180`，而正片 6665 秒），
  程序会在日志和界面里写明"这是试看"；`vkey` 有效期约 6 小时；
  纯 UGC 没有封面和简介（接口本身不提供）；
  分集标题只能一集一集问（接口的 `vids` 多值只返回第一条），已限制最多补 16 集以免太慢。

### 优酷

- **支持的输入**：`v.youku.com/v_show/id_{vid}.html`。
- **能拿到什么**：元数据走官方开放接口（标题 / 封面 / 时长 / 分类 / 发布时间 / UP主 /
  清晰度档位 / 付费标记），播放地址是移动页内嵌的**单文件直链**。
- **实测**：免费 UGC → 720P 单文件 3.4 MB，Range 返回 206、字节数与接口一致。
- **限制**：移动页**必须用移动端 UA**（桌面 UA 实测直接被风控拦掉）；
  匿名身份只能拿到优酷下发的那一档，**不能自选画质**；
  会员 / 付费内容不下发任何播放源，此时只给元数据并说明原因。

### 爱奇艺

- **支持的输入**：`www.iqiyi.com/v_{id}.html`。
- **能拿到什么**：元数据（标题 / 封面 / 简介 / 时长 / 频道 / 上映日期 / 付费标记）
  和分片直链。短号→`tvid` 的换算、以及 `cache.video.iqiyi.com/dash` 的 `vf` 签名
  都是从官方播放器 bundle 里读出来复现的，不依赖任何第三方库。
- **实测**：免费剧集《魅影神捕》第 1 集 → 8 段 720P 全片 416 MB；
  会员片《功夫女足》→ 2 段 720P 共 118 MB（约 6 分钟试看，正片 106 分钟）。
- **限制**：未登录最高只到 **720P（bid500）**，请求更高画质会被接口**静默降级**，
  程序会认接口实际下发的那条（标了 `_selected` 的才真正带分片表）并在说明里写清降级原因；
  会员片只有试看片段。

> 所有适配器都只用 **Python 标准库**，不装任何第三方包。
> 遇到风控、会员墙、地区限制时会**如实报错并写清原因**，不会伪造地址、也不会假装成功。

## 二、本地文件转换

把各音乐平台下载到的**加密专属格式**拖进来，解密成通用音频，再按你要的格式输出。
整条链路都在本机完成，**文件不会上传到任何地方**。

### 支持的加密格式

| 扩展名 | 平台 | 状态 |
|---|---|---|
| `.ncm` | 网易云音乐 | ✅ 完整（自带 AES-128-ECB 实现） |
| `.qmc0` `.qmc3` `.qmcflac` `.qmcogg` | QQ音乐（QMCv1） | ✅ 完整 |
| `.mflac` `.mflac0` `.mgg` `.mgg1` | QQ音乐（QMCv2） | ⚠️ 见下方说明 |
| `.kgm` `.kgma` `.vpr` | 酷狗音乐 | ✅ 完整 |
| `.kwm` | 酷我音乐 | ✅ 完整 |

标准库没有 AES，所以 NCM 需要的那部分是自己实现的（已通过 FIPS-197 标准测试向量）。

### 输出格式

`保持原格式` / `mp3` / `flac` / `m4a` / `wav` / `ogg` / `opus`

- **保持原格式**永远可用：纯 Python 流式复制，字节级无损，不碰音频数据
- 目标格式与源格式相同时同样直接复制，不需要 ffmpeg
- **真正需要重编码时必须有 ffmpeg**。没有时程序会**如实报错**
  （"需要 ffmpeg 才能转成 mp3：请先安装 ffmpeg，或改用「保持原格式」"），
  **不会**把 flac 改名成 .mp3 糊弄过去
- 音质档位说明：`bitrate` 只对 mp3 / m4a / opus 生效

### 标签写入

解密时解析出的元数据会写进输出文件，不依赖 ffmpeg：

- **MP3**：ID3v2.3 的 `TIT2` / `TPE1` / `TALB` / `APIC`（中文用 UTF-16 + BOM），
  会自动剥离旧的 ID3v2 与结尾的 ID3v1，认识的旧帧原样保留
- **FLAC**：Vorbis Comment（`TITLE` / `ARTIST` / `ALBUM` …）+ PICTURE 块
  （自动识别 PNG/JPEG/GIF 的 mime 与宽高深），改写时音频帧逐字节不变
- ogg / m4a / wav 不支持写标签，会原样保留、一个字节都不动

### 安全与稳健

- 解密后**校验文件头**（`fLaC` / `OggS` / `RIFF` / `ID3` / 帧同步 / `ftyp`），
  不对就抛错并删除临时文件 —— **绝不产出坏文件**
- 256 KiB 流式分块，40 MB 的文件峰值内存 0.8 MB
- 文件路径通过系统文件对话框获取，不需要把几百 MB 的文件走一遍 HTTP 上传

> ⚠️ **已知不支持**：QMCv2（`.mflac` / `.mgg`）的 `ekey` 解包（TEA 的轮数/端序细节未对齐，
> 公开测试向量只对上前 8 字节）—— 这类文件会**明确报错**而不会产出坏文件；
> 酷狗 `.kgg`（`crypto_version=5`，需要 `KGMusicV3.db`）未实现。

## 三、十条抓取通道（哔哩哔哩）

B 站是唯一做了多通道的平台：每条通道都是独立实现，有各自的接口、签名方式和失败模式。界面的「时间表」页会把同一个视频
丢给全部通道跑一遍，逐条报告**此刻这台机器上**的真实可用性 —— 而不是写死的宣传。

| # | 通道 | 做法 | 实测结果（未登录） |
|---|---|---|---|
| 1 | **Web WBI 签名接口** | `/x/player/wbi/playurl`，用 nav 下发密钥做 mixin_key 混洗 + `w_rid` 签名 | 可用 · DASH 480P |
| 2 | **单文件直取（fnval=1）** | 专门请求 durl 单文件 MP4 | 可用 · **720P 单文件，免合并** |
| 3 | **移动端 APP 接口** | 伪装 Android 客户端，appkey/appsec 全参数 MD5 签名 | 可用 · DASH 480P |
| 4 | **网页源码内嵌数据** | 抓 HTML，从 `__INITIAL_STATE__` 取元数据与站点内嵌的 `defaultWbiKey`，自己算密钥签名 | 可用 · 480P，**全程不请求 nav** |
| 5 | **HTML5 移动端接口** | `platform=html5&high_quality=1`，服务端直接回封装好的 MP4 | 可用 · 单文件 MP4 |
| 6 | **Web 经典接口（免签名）** | 裸调 `/x/player/playurl`，不签名 | 可用 · DASH 480P，WBI 失效时的兜底 |
| 7 | **番剧 / 影视 PGC** | `pgc/view/web/season` + `pgc/player/web/playurl`，处理 ep / ss 号 | 可用 · 番剧 480P（付费内容仅试看） |
| 8 | 第三方解析服务聚合 | 轮询 7 个公开解析接口挖直链 | 实测取流接口**全部失效** |
| 9 | 云视听 TV 端接口 | TV appkey 签名请求 `/x/tv/playurl` | 网关无条件返回 `-400` |
| 10 | 外部下载器（yt-dlp / lux） | 调用本机已有的成熟下载器；打包版可内置 | 可用 · **实测 1080P** |

**普通投稿视频开箱可用 6 条通道**（打包版装上 yt-dlp 后是 7 条），番剧另走 PGC 通道。第 8、9 条完整保留代码并在界面上
如实标注失效原因 —— 它们随时可能恢复，届时无需改动即可工作。

![通道体检](docs/screenshots/02-channels.png)

### 实测出来的几个关键事实

下面的结论来自本项目对 B 站接口的实测（原始证据见 [docs/channel-probe-report.md](docs/channel-probe-report.md)），
也是代码里那些"看起来奇怪"的写法存在的原因：

1. **未登录时 DASH 最高只有 480P，但 durl 单文件能给到 720P。**
   所以程序在「自动」模式下会比较两条通道的实际分辨率，挑画质更高的那条走。
2. **`accept_quality` 会虚报。** 未登录时接口声称支持 `[112, 80, 64, 32, 16]`，
   但 `dash.video` 里实际只有 480P 和 360P。因此界面只显示**真实下发到的档位**，
   虚报的那些画成虚线并标注「需登录 / 需大会员」。
3. **`window.__playinfo__` 在桌面播放页已经废弃**（页面上只剩一个恒为 undefined 的守卫）。
   但 `__INITIAL_STATE__.defaultWbiKey` 仍然可用，通道 4 正是靠它做到零 nav 请求。
4. **CDN 是双重防盗链**：必须同时带 `Referer: https://www.bilibili.com/` 和桌面 Chrome UA，
   否则一律 403。
5. **HTML 必须按 gzip 魔术字节解压**：服务端会无视 `Accept-Encoding: identity` 直接回 gzip。
6. **接口对突发请求非常敏感**，并发高了会吃 412。客户端因此实现了接口域名限速 +
   命中风控后全局冷却，并且只用 Range 探测长度（不带 Range 会真的把 20MB 全量拉下来）。

## 四、清晰度

各平台的画质体系完全不一样：B 站用 `qn` 码（127 / 120 / 80 …），
抖音按码率档下发 H.265/H.264，芒果TV 只在 m3u8 里给不同码率的子列表，
腾讯视频用 `vkey` 里带的格式等级。程序把**实际下发到的流**统一成一张列表，
用分辨率和码率横向比较，所以换平台不用换心智模型。

B 站的 13 档 `qn` 对照表：

| qn | 画质 | qn | 画质 | qn | 画质 |
|---|---|---|---|---|---|
| 127 | 8K 超高清 | 112 | 1080P+ 高码率 | 64 | 720P 高清 |
| 126 | 杜比视界 | 100 | 智能修复 | 32 | 480P 清晰 |
| 125 | HDR 真彩 | 80 | 1080P 高清 | 16 | 360P 流畅 |
| 120 | 4K 超清 | 74 | 720P60 高帧率 | 6 | 240P 极速 |
| 116 | 1080P60 高帧率 | | | | |

画质选择器有三层信息：**实际下发的档位**（可选）、**接口虚报的档位**（虚线 + 原因）、
以及每条流的分辨率 / 编码 / 码率 / 体积。B 站同一档画质会同时下发 H.264、H.265、AV1
三个版本，可以按需选择（默认 H.264，兼容性最好）。

**各平台的画质上限（均为实测）**：

| 平台 | 可选档位 | 提到更高会怎样 |
|---|---|---|
| 哔哩哔哩 | 480P / 720P（未登录） | 接口虚报但不下发，界面标成虚线 |
| 抖音 | 2160P / 1440P / 1080P / 720P / 576P / 540P | 按传入要求挑最接近的一档 |
| 小红书 | 平台下发的成品档 | — |
| 芒果TV | 720P / 576P / 480P | 1080P 需会员（`vip=1`，列成虚报档位） |
| 腾讯视频 | 480P → 自动升到 720P | 会员片只给约 180 秒试看 |
| 优酷 | 平台下发的单一档位 | **不能自选画质** |
| 爱奇艺 | 最高 720P（bid500） | 请求 1080P 会被**静默降级**，程序认实际下发的那条 |

想要 B 站 1080P 及以上，需要在「设置 → 平台账号与凭据」的**哔哩哔哩区块**里填入 `SESSDATA`；
4K / HDR / 杜比另需大会员。其它六个平台目前都无需登录即可使用。

### 平台凭据是怎么组织的

每个平台需要什么凭据，由**适配器自己声明**（`videograb/sites/*.py` 里的 `credentials`），
设置页只负责渲染。所以：

- **一个平台一个独立区块**，标题就是平台名，带该平台的品牌色圆点，绝不会混在一起；
- 每个凭据都写清**用来换什么**（例如"SESSDATA 解锁 1080P 及以上"）；
- 每个凭据都自带**分步获取说明**，折叠在区块里，不用去翻文档；
- 明确标注风险（哪些值等同登录凭证、只存在本机、何时失效）；
- 不需要任何凭据的平台会统一列在末尾的「无需登录的平台」一行里。

目前只有哔哩哔哩需要凭据（`SESSDATA` 必需、`bili_jct` 可选），其余六个平台声明为空列表。
以后某个平台开始需要 Cookie 时，只要在它的适配器里加一段声明，界面会自动多出一个区块。

## 五、下载与合并

- **分块多线程**：默认 8 连接，4MB 一块，块级断点续传（中断后重跑自动跳过已完成的块）
- **主备 CDN 自动切换**：主地址失败会依次尝试 `backupUrl` 里的其它 CDN
- **HLS 分片下载**：芒果TV 这类只给 m3u8 的平台，按播放列表逐片下载再拼接成文件
  （未加密的 MPEG-TS，纯标准库即可；带 #EXT-X-KEY 加密时会明确报错而不是产出坏文件）
- **分 P 勾选批量下载**：多 P 视频会列出每一 P 的标题和时长，勾选后逐个建立独立任务
  （每个 P 的进度、重试、失败原因互不影响），带全选 / 反选 / 清空
- **五种下载模式**：自动 / 单文件 MP4（免合并）/ 强制 DASH / 仅音频 / 仅元数据
- **附加产物**：封面（所有平台）、Kodi / Jellyfin 可识别的 NFO（所有平台）、
  XML 弹幕 + 转好的 ASS 字幕、CC 字幕转 SRT（**弹幕与字幕目前只有 B 站能拿到**，
  其它平台不会去做无意义的请求）
- **任务历史落盘**，重启后仍在；上次没跑完的会标成「已中断」，可一键重试

### 内置 fMP4 合并器

B 站的 `.m4s` 是 CMAF 分片格式：`ftyp → free → moov → sidx → (moof → mdat)*`
（`moov` 里的样本表是空的，真正的样本信息全在 `moof/traf/trun` 里）。
因此**不需要重新编码**，只要：

1. 各取一次两个流的 `ftyp + moov`
2. 把两条轨道的 `moov` 合成一个：合并 `mvhd`、两条 `trak`、
   `mvex`（`mehd` / `trex` / `trep`），音频轨改号并同步改写
   `tkhd.track_ID` 与 `trex.track_ID`
3. 按 `tfdt` 解码时间把两边的 `moof + mdat` 交错写出，同时把音频分片的
   `tfhd.track_ID` 改成新号

输出结果经过实际解码验证：合并得到的 MP4 在 Chrome 里能正常播放，
时长 212.31 秒、分辨率 853×480，与源流一致。

如果本机装了 ffmpeg，程序会优先用它（`-c copy` 重封装）；没有就自动走内置合并器，
两条路径对用户透明。

## 十、自己打包成 exe

`build.py` 会自动建一个构建用的虚拟环境并安装 PyInstaller，不需要你事先准备任何东西：

```bat
python build.py                     :: 单文件便携版（默认）
python build.py --onedir            :: 目录版，启动更快
python build.py --all               :: 两种都打
python build.py --onedir --with-ytdlp    :: 顺手把 yt-dlp 一起打进去
python build.py --with-webview2          :: 内置 WebView2 引导程序（+1.9MB）
python build.py --onedir --with-ffmpeg   :: 顺手把静态 ffmpeg 一起打进去（约 +80MB）
```

打包做了这几件事：

1. 用 Pillow 现场画一个多尺寸 `.ico`（纯图形，不依赖字体或 SVG 渲染器）
2. 建 `.build-venv` 并安装 PyInstaller —— 不污染系统 Python
3. 把 `web/` 整个界面资源通过 `--add-data` 打进包里
4. 排除 `tkinter` / `numpy` / `PIL` 等用不到的模块控制体积
5. `--with-ytdlp` 时把 yt-dlp 装进 `.deps` 再 `--collect-all` 收进 exe

### 打包版里 yt-dlp 是怎么工作的

exe 里的 `sys.executable` 是 `Video-Grabing.exe` 而不是 python，
所以 `python -m yt_dlp` 这种调用方式在打包后会失效，`pip` 也不存在。
通道 10 因此走了一条**进程内**路径：直接把 `yt_dlp` 当普通模块导入并调用它的 Python API，
不需要任何外部解释器。相应地，打包版里的「一键安装 yt-dlp」按钮会改为提示
「把 yt-dlp.exe 放进 bin 目录」而不是尝试联网安装。

**顺带一个实测收获**：内置 yt-dlp 这条通道能拿到 **1080P**，
而官方那几条通道在未登录时最高只有 480P（durl 720P）。
实测下载并合并出的 1080P 文件在 Chrome 里解码正常：1920×1080、212.31 秒。
所以想要免费的高画质，第 10 条通道是最划算的一条。

## 十一、独立桌面窗口

程序**不依赖浏览器**。启动后是一个属于本进程的原生窗口，任务栏图标、标题、尺寸都由自己控制。

### 永远不会弹出浏览器

这一点是硬性行为：**任何情况下都不会自动打开系统浏览器**。

1. **内置 WebView2 窗口** —— 首选。pywebview + pythonnet 驱动 WebView2 运行时，窗口属于本进程
2. **Edge 应用模式** —— 退而求其次：`msedge --app=`，无标签栏无地址栏，看起来仍是独立窗口
3. **原生对话框** —— 前两者都起不来时，弹一个系统对话框说明原因、给出服务地址和补救办法

服务始终在后台运行，对话框里会写明地址，**要不要用浏览器打开由你自己决定**。
只有显式加 `--browser` 参数才会走浏览器。

> 早先的版本在第 3 步会直接 `webbrowser.open()`，用户点的是桌面程序、出来的却是网页标签页，
> 既莫名其妙又看不出哪里出了问题。现在不会了。

### WebView2 运行时怎么带

Windows 上内嵌浏览器需要一个 **WebView2 运行时**。绝大多数 Win10/11 上它随 Edge 预装了，
但确实有机器没有。四种做法按体积代价排列，构建时自己选：

| 做法 | 体积代价 | 说明 |
|---|---|---|
| 什么都不做 | **+0** | 依赖系统已有的运行时 |
| `--with-webview2` | **+1.9 MB** | 内置官方引导程序，缺失时可一键联网安装 |
| `--with-webview2-full` | **+204 MB** | 内置完整离线包，不需要网络 |
| **固定版本运行时** | **+180~250 MB** | **真正的封装**：完全不依赖系统 |

最后一种是把某个具体版本的运行时整个放进程序目录的 `webview2\` 子目录，
程序启动时会自动检测并通过 `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` 让 WebView2 加载器改用它 ——
**连没装 Edge 的干净系统也能开出独立窗口**。

「设置 → 更新与自检」里会显示当前用的是哪种运行时。

HTTP 服务仍然跑在后台，但只监听 `127.0.0.1`，且所有写操作都要带一次性令牌 +
校验 `Origin` / `Host` —— 否则浏览器里任意网页都能跨站调用本机接口
（比如把代理改到攻击者的服务器上，把 SESSDATA 骗走）。

## 十二、自动更新与自检修复

仓库里有 `update/manifest.json`，记录每个界面文件的 SHA-256。

- **自检**：把本地文件逐个算哈希比对，报出缺失 / 被改动 / 读不了的文件
- **修复**：从更新源重新下载并覆盖。只要有一个界面文件不对，就把整个 `web/` 重下一遍 ——
  因为 exe 同级的 `web/` 是一个**覆盖层**，必须自洽，不能一半新一半旧
- **更新**：比对版本号，有新版可一键下载安装包（下载后校验 SHA-256 再允许运行）

```bat
python start.py update              :: 检查更新
python start.py update --verify     :: 只自检，不改动任何文件
python start.py update --repair     :: 自检并修复
python start.py update --download   :: 有新版时直接下载安装包
```

### 关于更新源

实测在部分网络下 `raw.githubusercontent.com` 完全不可达，所以更新源按可达性排序：

1. `cdn.jsdelivr.net/gh/PLSSJX/BLG@main/`（优先）
2. `raw.githubusercontent.com/PLSSJX/BLG/main/`（兜底）

断网时还能用包里自带的那份基线做离线自检（这份不含安装包哈希，因为构建顺序决定了它必然比发布版旧）。

### 打包后怎么修

exe 里的代码封在 PyInstaller 的解包目录里，改不了。所以 `web/` 的解析顺序是
**「exe 同级的 web/ 覆盖层」优先，其次才是包内的只读副本** —— 修复程序把文件下到覆盖层，
重启后即生效。

## 十三、已知限制

- **各平台的能力边界见第一节**，那里写的是实测结果，不是宣传口径。
- **未登录画质上限**：B 站官方通道 DASH 480P / 单文件 720P，更高需要 `SESSDATA`；
  但第 10 条通道（内置 yt-dlp）实测可以直接拿到 1080P。
- **音乐平台的免登录档位**：网易云 320K / 酷狗 128K–Hi-Res 母带 / 酷我 128K / QQ音乐 免费歌 128K。
  无损一般都要填对应平台的 Cookie，程序会把拿不到的档位列成虚报档位并说明原因。
- **会员内容**：B 站的 4K / HDR / 杜比、腾讯与爱奇艺的会员剧集、优酷的付费片，
  都只会下发平台愿意给的那部分（试看片段、低画质或干脆不给）。程序会如实说明，
  不会假装下到了全片。
- **平台接口随时会变**：这些适配器依赖的都是各家当前的公开路径，风控一升级就可能失效。
  真失效时程序会明确报错并写清卡在哪一步，而不是给你一个坏文件。
  界面上「通道」页也能随时看到 B 站十条通道此刻的实际可用性。
- **本地转换的真实重编码没验证过**：本机没有 ffmpeg，所以 flac → mp3 这类转换
  只验证了参数构造与"没有 ffmpeg 时如实报错"的路径，**没有用真实编码器产出过文件**。
  想用这个功能请先装 ffmpeg（或用 `build.py --with-ffmpeg` 构建）。
- **加密格式解密有两个缺口**：QMCv2 的 `.mflac` / `.mgg`（ekey 解包未对齐）和酷狗的 `.kgg`。
  前者会明确报错、不会产出坏文件；后者未实现。
- **带真实 Cookie 解锁无损的分支没实测过**：四个音乐平台都只测了免登录档位，
  开发机上没有会员账号，所以"填了 Cookie 之后能不能真的拿到无损"未经验证 ——
  代码只按服务端实际下发的档位判断，拿不到就报错，不会伪造。
- **第三方解析与 B 站 TV 端当前已失效**，通道保留待其恢复。
- **合规提醒**：请仅将本工具用于**个人学习与备份自己有权访问的内容**。
  各平台的服务条款都禁止未授权的抓取与二次分发，请不要把下载的内容用于传播或商业用途。
