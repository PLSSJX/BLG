# 项目功能 · 原型（已接真 git）

独立原型目录，不碰现有应用。真 git、真文件、真冲突。

## 启动

```
cd prototype
python server.py           # http://127.0.0.1:8899
```

浏览器打开 **http://127.0.0.1:8899**。不启服务时双击 index.html 只能看静态视觉。

## 能力清单

| 能力 | 说明 |
|---|---|
| 新建项目 | 空文件夹校验 → `git init` → `.mt/graph.json` + `PROJECT.md` → 首次提交 |
| 节点 ↔ 文件 | 双击节点写正文 → 落成 `.md` → 节点显示摘要 + 文件名 |
| 外部编辑 | 满足「内容变了 + 没进程占用 + 静默 30 秒」就自动提交 |
| 摘要同步 | 外部改 `.md` → 节点摘要自动更新（可关） |
| 挂文件（镜像） | 复制到 `assets/<节点名>/`，改副本不动源文件 |
| 大文件 | >5MB 不进 git，只记 size/mtime；需要时算 SHA-256 |
| 历史 / 回滚 | 整体回滚 + **单文件回滚** |
| 分支 | 新建 / 切换 / 合并 / 删除（未合并会二次确认） |
| 冲突 | 逐文件「用我的 / 用对方」，或放弃合并 |
| 删除节点 | 连带子孙，先确认数量和文件数，可选择性删文件 |

## 删除的安全约束（重点）

```
主干不可删                     接口层直接拒绝
删父节点 → 连带所有子孙         用 visited 集合防环，环状数据 33ms 内完成
不存在的 id                    报错而不是静默成功
删节点默认保留 .md 文件         显式勾选才删
附件目录空了自动清理            不留空壳
文件被占用删不掉                failed_files 回传，界面提示
```

## 画布操作

| 操作 | 效果 |
|---|---|
| 拖动空白处 | 整体平移画布 |
| 滚轮 | 以指针为中心缩放（0.35x–2.5x） |
| 双击空白 | 视图复位 |
| 拖动节点靠近别的节点 | 出现流动虚线预告，松手即连（正下方=分支，右侧=主线） |
| 拖动任意节点 | 自动切换成自由摆放，不会被拉回原位 |
| 右键连线 | 编辑说明 / 断开连接 |
| 点节点右下角 📎 | 展开附件列表，点文件名直接打开 |
| 编辑面板「类型」 | 自动 / 主干 / 分支，决定吸附方向 |
| 双击节点 / 选中后按 Enter 或 F2 | 打开编辑面板 |
| 编辑面板「关联节点…」→ 点另一个节点 | 建立关联线（紫色点线，与结构无关） |
| 点关联线 | 删除这条关联 |
| 点关联线上的文字 | 修改说明（建线时也会问一句） |
| 工具栏「自动排版」 | 关闭后节点可以任意摆放，不再自动排列 |

自动排版带**防重叠兜底**：按 y 排序逐个检查，发现重叠就把靠下的节点往下推开（16px 间距），
最多迭代 80 轮，宁可留白也不叠字。

点阵背景画在外层容器上并跟随平移缩放，所以拖到多远都有网格；
SVG 设了 overflow: visible，超出视口的连线也不会被裁掉。

节点右下角有 📎 角标表示挂了文件。

## Markdown 编辑器

节点正文用「编辑 / 分栏 / 预览」三档，工具条能一键插标题、粗体、斜体、行内代码、列表、引用、链接。

渲染器是自己写的（`js/md.js`），**先转义 HTML 再生成标签**，原文里的 `<img onerror=...>` 只会当文本显示。

```
支持：标题 加粗 斜体 删除线 行内代码 代码块 列表 引用 分割线 链接
```

## 冲突怎么处理

```
分支面板 → 冲突列表 → 逐段处理
```

每一段冲突左右并排显示「我的 / 对方的」，点哪边留哪边，也可以
「两个都留」或「这段都不要」。全部处理完 → 保存并标记已解决 → 提示完成合并。

只想快速了事时，也有「整体用我的 / 整体用对方」。

## 合并期间的保护

合并冲突时工作区里带着 `<<<<<<<` 标记，**自动提交绝不能碰**：

```
.git/MERGE_HEAD 存在  → 自动提交暂停，状态条显示「正在合并」
文件里还有冲突标记    → 即使强点「立即提交」也会被拒绝
```

（这条是踩过的坑：早期版本把带冲突标记的文件提交进历史，还顺带把合并完成了。）

## 删除后怎么撤销

每次删除都**立刻单独提交**，所以随时能回来。三条路：

```
① 删除后的提示条上点「撤销」      ← 最快，git revert 一步到位
② 历史面板里点那次提交 → 整体回滚   ← 想回到更早的状态
③ 历史面板里展开提交 → 单文件回滚   ← 只恢复某个文件
```

撤销用的是 `git revert`，不是 `reset`：

```
历史会多一条 Revert "mt: 删除节点…"
删除那条记录仍然在历史里，任何时候都能翻出来
删掉的文件、附件都会一起回来
```

实测：

```
删 B（单节点）      → 撤销后 A,B 都回来了
删 C（连文件一起）  → 撤销后节点和 .md 内容都回来了
```

## 自动提交的三个条件

```
① 内容真的变了     size+mtime+hash（>4MB 只比 size+mtime）
② 没有进程持有     Windows Restart Manager
③ 静默 30 秒       MT_QUIET_SECONDS 可覆盖（测试用 4）
```

编辑器适配：VS Code/Typora 不锁 → 靠①③；Word/WPS 有 `~$` 锁文件 → 忽略前缀 + ②；VS 短暂写入 → 两次轮询一致才算稳定。

## 目录结构

```
<项目文件夹>/
├── .git/
├── .gitignore        大文件托管区块
├── .mt/
│   ├── graph.json    结构：主干、节点、方向、暂存区
│   ├── large.json    大文件清单
│   └── settings.json { auto_summary }
├── assets/<节点名>/   挂上来的文件副本
├── PROJECT.md
└── …正文 .md
```

## 服务端

- 只监听 `127.0.0.1`
- 只对登记表里的项目执行 git
- 所有路径校验必须落在项目目录内
- git 一律参数列表，不拼 shell
- 线程异常写入 `_server.log`（不再静默失败）
- 锁检测用纯 Python 探测（早期版本用 ctypes 调 Restart Manager，64 位下会崩进程）
