# 端到端测试

六个脚本都直接打本机正在运行的 MakiseToolkit（默认 127.0.0.1:8931），
所以**先启动应用**再跑。

    node tests/e2e/api.mjs                      # 接口层（23 项）
    node tests/e2e/ui.mjs                       # 画布层（23 项）
    node tests/e2e/header.mjs                   # 左上角按钮 + 删除项目（15 项）
    node tests/e2e/scenarios/lifecycle.mjs      # 节点与文件生命周期（86 项）
    node tests/e2e/scenarios/branch-merge.mjs   # 分支/合并/回滚/导出（82 项）
    node tests/e2e/scenarios/edge-cases.mjs     # 边界值与异常（80 项）
    node tests/e2e/buttons.mjs                  # 画布页每个按钮逐个点（41 项）
    node tests/e2e/buttons-list.mjs             # 列表页与新建立/改名/删除（17 项）
    node tests/e2e/link.mjs                     # 下载结果存进项目（联动，8 项）

## 跑完之后

每套脚本都会在 `D:\` 或系统临时目录下建测试项目，并登记进 `data/projects.json`。
跑完记得清一次（不会碰「演示项目」和你自己的项目）：

```
python scripts/prune_test_projects.py --dry   # 先看会删什么
python scripts/prune_test_projects.py         # 真删
```

判定规则：名字像测试用例、路径在临时目录或以 `_` / `mt-` 开头、登记的目录已经不在了。
三类任一命中就删，所以忘了删的旧条目也会被这次一并带走。

约定：

* 每个脚本用独立临时项目目录和独立浏览器配置目录
* 全部通过时退出码 0，最后一行为 `结果: x/y`
* api.mjs 里有 30 秒静默窗口的自动保存测试，单个脚本约 1 分钟

### copy.mjs — 文案自检（不启浏览器，几秒跑完）

扫源码里**用户看得见的文字**（JS 字符串字面量、HTML/MD 可见文本，注释不算），四条规则：

| 规则 | 查什么 |
| --- | --- |
| 口语词 | 搞定 / 随便 / 算了 / 点左边 / 存好了 这类聊天腔 |
| AI 腔 | 「不是…而是…」「值得注意的是」「首先…其次」等对仗套话 |
| 旧术语 | 已经改过名的说法（附加工具箱 / 文献检索 …）又漏回来 |
| 残留与空壳 | TODO / FIXME / 占位文字，以及 onclick 为空、href="#" 的死入口 |

外加两项结构检查：界面内术语是否混用（节点/卡片、回退/回档），
以及已删除的重复入口有没有复活。

跑法：`node tests/e2e/copy.mjs`（通过时打印「文案检查通过」）

### data-safety.mjs — 数据安全专项（24 项）

论文工具最不能接受的是丢稿，这套是专门盯这个的。**它会自己杀进程再拉起来，不能和其它套件并行跑。**

| 组 | 验证的事情 |
| --- | --- |
| ① | 首次提交能落地 |
| ② | 15 次快速保存后正文是最新一次，版本没漏 |
| ③ | 回档到旧版本后再写再回档，没有「幽灵内容」 |
| ④ | 编辑中 `taskkill /F` 强杀 → 重启后内容与历史都在 |
| ⑤ | 断电模拟（直接改盘上的 .md 再强杀）→ 内容不丢、还能继续提交 |
| ⑥ | 100+ 版本时时间线加载与回档耗时（实测 40ms 量级） |
| ⑦ | 一键备份出的 zip 里含 `.mt/` 版本库与正文 |
| ⑧ | 挂载的附件是**副本**：改原文件不影响项目里的那份 |
| ⑨ | 版本库目录被删掉后，重新打开项目能自动重建且正文完好 |
| ⑩ | 版本库文件被写坏（断电截断/手滑覆盖）后：项目仍能打开、正文完好、还能保存、能重新开始记版本 |

**关于「JSON 迁移到 SQLite」这一项**：本程序从 3.x 起就没有 JSON 版本库 ——
4.0 的版本库一开始就是 SQLite（`.mt/history.db`），不存在格式迁移。
真正会遇到的等价风险是「库文件不存在 / 库文件损坏」，分别由 ⑨ 和 ⑩ 覆盖：

* 库文件不见了 → 自动重建空库，正文不动
* 库文件坏了 → 先把坏库改名成 `history.db.broken-<时间>` 留档，再建新库；
  正文和项目照常打开，历史从空开始记（坏库留着，需要时可以人工抢救）

跑法：
```
node tests/e2e/scenarios/data-safety.mjs
```
